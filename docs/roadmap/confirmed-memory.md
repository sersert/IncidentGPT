# Confirmed incident memory

Resolution confirmation is a separate human workflow. An AI analysis, helpful rating or resolved alert does not create a confirmed solution. Existing feedback remains independent and is not backfilled into knowledge.

`GET/PUT /api/v1/incidents/{id}/resolution` requires backend-verified Basic credentials, persistent Redis and an accessible incident. PUT carries the last observed revision (0 for first write) and status confirmed/unknown/withdrawn. Confirmed requires a cause, restoring action and available evidence owned by this incident. Actor/time are set by the backend from verified credentials/UTC, never an actor header. Unknown explicitly clears cause. Records retain unsuccessful attempts, verification IDs, environment/version, failure mode/error signature and safe HTTPS links. Sanitization precedes persistence. A stale revision returns 409; sanitizer or storage failures return 503 rather than success.

Atomic Redis updates retain every resolution revision at `igpt:resolution:history:<id>:<revision>`, update current `igpt:resolution:<id>`, and add/remove cluster/service indexes. Correction or withdrawal immediately changes future retrieval; historical versions remain for audit. Retention follows incident retention (no automatic deletion). Include resolutions and indexes in Redis backups; rebuild indexes from explicit retained resolutions if restoring a partial archive, not from AI guesses. The existing deployment has shared-admin access, not per-team tenancy; cluster-aware lookup prevents accidental cross-cluster matches but does not claim tenant isolation.

`GET /api/v1/knowledge/search?incident_id=<id>` binds cluster/service to the incident. Explicit cluster_id/service parameters support scoped manual search; unknown cluster yields a useful empty/unknown state. `q`, offset and limit provide bounded text filtering and pagination. At most 200 recent indexed candidates are examined, with an explicit candidate_limit_applied flag. Ranking explains service/workload match, failure/alert type and normalized text/error-signature match. Scores are ranking points, not probabilities. Environment/version differences or unknown values remain visible. Only current confirmed records are authoritative. An incident does not retrieve itself. Existing `results/total` response envelope is preserved; new cards consume the structured resolution record rather than the old mock-only scalar solution shape.

`GET /api/v1/knowledge/patterns?cluster_id=<id>&service=<optional>` returns deterministic failure-mode counts within the latest 200 confirmed scoped candidates, with X-Candidate-Limit. Counts are bounded-window observations, not global historical totals. Queries without cluster scope return an empty list. Both knowledge endpoints enforce the same backend reader access and expose storage errors.

## Local Markdown runbooks

Set RUNBOOK_DIRECTORY to a configured read-only local directory. In Helm, mount `runbooks.existingConfigMap` at `/etc/incidentgpt/runbooks` and set env RUNBOOK_DIRECTORY to that path. Disabled when no directory is configured; no external collector or repository crawling is introduced. Projected ConfigMap symlinks are accepted only when their canonical targets stay within the configured root. Outside links, non-regular files and oversized documents fail rather than reading arbitrary files.

At most 100 directory entries, 64 KiB per source and five results per request; excerpts are bounded to 4096 bytes. Each result has a stable document identity, version/content hash, title, local modification time and collection time. Sanitization precedes return and immutable Redis version snapshots (`igpt:runbook:version:*`, 30-day TTL). Sanitizer/source failures produce unavailable or partial runbook status independently of confirmed solution visibility. Plain text snippets are untrusted cited data; no document instructions execute, and no retrieved URL is fetched. A changed document produces a new hash/snapshot rather than silently rewriting provenance.

Rollout requires reader credentials and the existing sanitizer connection; no knowledge is fabricated on a clean installation. Add a small reviewed runbook directory only if desired. Rollback removes the new UI/routes or unsets RUNBOOK_DIRECTORY; additive resolution/evidence/history keys remain readable by compatible versions. No destructive backfill is required. Disabling retrieval must not delete incident or feedback history.
