# Настройка Telegram для IncidentGPT

Эта инструкция проведет вас от пустого Telegram до готовой конфигурации IncidentGPT. Вы создадите одного Telegram-бота, один Telegram-канал и одну связанную группу обсуждения.

Схема работы:

```text
Alertmanager
    |
    v
IncidentGPT
    |
    v
Telegram-бот
    |-- публикует инциденты в Telegram-канал
    `-- работает со связанной группой обсуждения
```

| Сущность | Для чего нужна |
|----------|----------------|
| Telegram-бот | Техническая учетная запись, от имени которой IncidentGPT отправляет сообщения |
| Telegram-канал | Лента, куда публикуются инциденты |
| Telegram-группа | Чат для обсуждений и комментариев к публикациям канала |

> [!IMPORTANT]
> Telegram-группа уже является чатом. Не нужно создавать отдельные "группу" и "чат". Необходимо создать: одного бота, один канал и одну группу обсуждения.

## Как IncidentGPT использует Telegram

Текущий код `ai-worker` отправляет сообщения через Telegram Bot API `sendMessage`.

Что делает `ai-worker`:

1. Публикует сырой алерт в `TELEGRAM_CHANNEL_ID`.
2. Для группы связанных алертов публикует сводку в `TELEGRAM_CHANNEL_ID`.
3. Публикует AI-разбор как reply к сообщению канала через `reply_to_message_id`.
4. Не отправляет параметр `message_thread_id`.
5. Не читает обычные сообщения группы.
6. Не вызывает `getUpdates` во время штатной работы.

`TELEGRAM_THREAD_CHAT_ID` в текущей конфигурации означает ID связанной группы обсуждения. Код загружает эту переменную, показывает ее в `/status` как `thread_chat_configured`, а если она пустая, подставляет `TELEGRAM_CHANNEL_ID`. При отправке сообщений текущая реализация использует `TELEGRAM_CHANNEL_ID`; комментарии появляются в связанной группе за счет настройки канала Telegram.

> [!NOTE]
> `TELEGRAM_THREAD_CHAT_ID` не является ID темы форума. В текущем коде нет отдельной настройки для `message_thread_id`.

Текущий формат публикаций:

| Тип сообщения | Где публикуется | Формат |
|---------------|-----------------|--------|
| Сырой алерт | `TELEGRAM_CHANNEL_ID` | `[STATUS] alertname (severity)`, затем `Labels`, `Annotations`, время `Starts` и `Source` |
| Сводка группы | `TELEGRAM_CHANNEL_ID` | `[STATUS] N связанных алертов (group_key)`, затем список алертов |
| AI-разбор | reply к сообщению канала | Структура из LLM: первопричина, исправление, профилактика; длинный текст режется на части до 4000 символов |

## Шаг 1. Создайте Telegram-бота через BotFather

1. Откройте Telegram.
2. В поиске введите `@BotFather`.
3. Откройте официальный аккаунт.
4. Проверьте, что username равен `BotFather`.
5. Нажмите `Start`.
6. Отправьте команду:

```text
/newbot
```

7. Когда BotFather попросит имя бота, введите отображаемое имя:

```text
IncidentGPT Orange
```

8. Когда BotFather попросит username, введите уникальное имя, которое заканчивается на `bot`:

```text
orange_incident_bot
```

9. Скопируйте токен, который пришлет BotFather.

Пример формата токена:

```text
1234567890:AAExampleTokenDoNotUse
```

> [!WARNING]
> Это только пример. Не используйте его как настоящий токен.

В конфигурации IncidentGPT этот токен соответствует переменной:

```bash
TELEGRAM_BOT_TOKEN="<TOKEN_FROM_BOTFATHER>"
```

### Как понять, что все получилось

- BotFather сообщил, что бот создан.
- В сообщении BotFather появилась ссылка на бота.
- Вы получили токен.
- Личный чат с ботом открывается.
- Команда `/start` отправляется боту без ошибки.

### Если username уже занят

1. Не меняйте уже созданный токен.
2. Придумайте другой username.
3. Убедитесь, что username заканчивается на `bot`.
4. Попробуйте один из вариантов:

```text
incidentgpt_orange_bot
orange_incident_bot
my_incidentgpt_bot
```

Username должен быть уникальным во всем Telegram.

## Шаг 2. Настройте Privacy Mode

Для штатной работы IncidentGPT отключать Privacy Mode не обязательно.

Причина: текущий `ai-worker` не читает обычные сообщения группы. Он только отправляет сообщения через `sendMessage`. Команды вида `/test@username_bot` бот получает даже при включенном Privacy Mode, и этого достаточно, чтобы вручную получить ID группы через `getUpdates`.

Отключайте Privacy Mode только если вы отдельно дорабатываете проект так, чтобы бот читал обычные сообщения группы.

Если вам все-таки нужно отключить Privacy Mode:

1. Откройте `@BotFather`.
2. Отправьте команду:

```text
/setprivacy
```

3. Выберите созданного бота.
4. Выберите `Disable`.
5. Дождитесь подтверждения от BotFather.

## Шаг 3. Создайте группу обсуждения

Группа - это чат. Отдельный чат после создания группы не нужен.

Примеры названия:

```text
IncidentGPT Discussion
```

```text
inc orange chat
```

### Telegram Desktop

1. Откройте Telegram Desktop.
2. Нажмите кнопку создания нового чата.
3. Выберите `New Group`.
4. Выберите хотя бы одного временного участника, если Telegram требует участника для создания группы.
5. Введите название группы.
6. Нажмите `Create`.
7. Откройте настройки группы.
8. Если группа должна быть закрытой, оставьте ее приватной.

### Мобильный Telegram

1. Откройте Telegram на телефоне.
2. Нажмите кнопку создания нового сообщения.
3. Выберите `New Group`.
4. Выберите участника, если Telegram требует это действие.
5. Введите название группы.
6. Нажмите `Create`.
7. Откройте профиль группы.
8. Проверьте, что это группа, а не канал.

Темы форума для текущей реализации не обязательны, потому что код не отправляет `message_thread_id`.

Если вы хотите включить темы для ручного удобства:

1. Откройте группу.
2. Откройте управление группой.
3. Откройте `Темы`.
4. Нажмите `Включить`.
5. Проверьте, что появилась тема `General`.

> [!IMPORTANT]
> Не используйте ID темы `General` вместо ID группы. IncidentGPT сейчас ожидает chat id группы в `TELEGRAM_THREAD_CHAT_ID`, а не ID темы.

## Шаг 4. Добавьте бота в группу

1. Откройте группу.
2. Откройте управление группой.
3. Выберите `Администраторы`.
4. Нажмите `Добавить администратора`.
5. Найдите бота по username, например `orange_incident_bot`.
6. Добавьте бота.
7. Выдайте минимальные права.

| Право | Обязательно | Зачем |
|-------|-------------|-------|
| Отправка сообщений | Да | Нужна для ручной проверки `sendMessage` в группу и для будущих сценариев обсуждения |
| Управление темами | Нет | Текущий код не отправляет `message_thread_id` и не управляет темами |
| Удаление сообщений | Нет | Не требуется для штатной работы |
| Добавление участников | Нет | Не требуется |
| Закрепление сообщений | Нет | Текущий код не закрепляет сообщения |

### Как проверить

- Бот отображается в участниках группы.
- Возле бота есть отметка администратора.
- В правах бота разрешена отправка сообщений.

## Шаг 5. Создайте Telegram-канал

Канал - это лента публикаций. Группа - это обсуждения. Бот - это отправитель.

Примеры названия:

```text
IncidentGPT Alerts
```

```text
inc orange
```

Приватный канал подходит.

### Создание приватного канала

1. Откройте Telegram.
2. Нажмите кнопку создания нового чата или сообщения.
3. Выберите `New Channel`.
4. Введите название канала.
5. Нажмите `Create`.
6. Выберите `Private Channel`.
7. Сохраните канал.

### Как проверить, что это канал

- Вверху отображается количество подписчиков, а не участников.
- Поле ввода называется `Публикация` или похоже на него.
- Это не форум.
- В канале нет темы `General`.

### Как не перепутать канал и группу

| Признак | Канал | Группа |
|---------|-------|--------|
| Люди называются | Подписчики | Участники |
| Основное назначение | Публикации | Общение |
| Темы General | Нет | Могут быть |
| Права бота | Публиковать сообщения | Отправлять сообщения |

## Шаг 6. Привяжите группу к каналу

1. Откройте канал.
2. Откройте управление каналом.
3. Выберите `Обсуждение`.
4. Выберите созданную группу.
5. Подтвердите привязку.

Результат:

- новые публикации канала будут появляться в связанной группе;
- под публикациями появится возможность обсуждения;
- удалять группу или создавать еще один чат не нужно.

### Как проверить

1. Откройте настройки канала.
2. Найдите раздел `Обсуждение`.
3. Проверьте, что там указано имя вашей группы.
4. Опубликуйте тестовое сообщение в канал.
5. Откройте группу.
6. Проверьте, что тестовая публикация появилась в группе обсуждения.

Telegram может отправить служебное сообщение о привязке. Это нормально.

## Шаг 7. Добавьте бота администратором канала

1. Откройте канал.
2. Откройте управление каналом.
3. Выберите `Администраторы`.
4. Нажмите `Добавить администратора`.
5. Найдите созданного бота по username.
6. Добавьте бота.
7. Включите право `Публиковать сообщения`.
8. Сохраните изменения.

| Право в канале | Нужно текущему коду |
|----------------|---------------------|
| Публиковать сообщения | Да |
| Редактировать сообщения | Нет |
| Удалять сообщения | Нет |
| Управлять историями | Нет |
| Добавлять подписчиков | Нет |

### Как проверить

- Бот присутствует в списке администраторов канала.
- У него включено право публикации.
- Новый пост можно отправить через Telegram Bot API `sendMessage`.

## Шаг 8. Получите ID группы

> [!WARNING]
> Никогда не отправляйте URL с токеном другим людям и не публикуйте его в issue, документации или скриншотах.

1. Откройте группу обсуждения.
2. В теме `General` или в обычном чате группы отправьте команду:

```text
/test@BOT_USERNAME
```

Пример:

```text
/test@orange_incident_bot
```

3. Откройте в браузере URL. Подставьте настоящий токен вместо `<TELEGRAM_BOT_TOKEN>`:

```text
https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/getUpdates
```

4. Найдите объект с `message.chat.type` равным `supergroup`.
5. Скопируйте значение `message.chat.id` целиком, включая минус.

Обезличенный пример:

```json
{
  "ok": true,
  "result": [
    {
      "update_id": 111111111,
      "message": {
        "message_id": 25,
        "from": {
          "id": 222222222,
          "is_bot": false,
          "first_name": "Example"
        },
        "chat": {
          "id": -1001234567890,
          "title": "IncidentGPT Discussion",
          "type": "supergroup"
        },
        "text": "/test@orange_incident_bot"
      }
    }
  ]
}
```

Результат:

```bash
TELEGRAM_THREAD_CHAT_ID="-1001234567890"
```

Что важно:

- `type: "supergroup"` означает, что это группа.
- ID обычно начинается с `-100`.
- Знак минус нельзя удалять.
- `message_id` не является ID группы.
- `update_id` не является ID группы.
- `from.id` - ID пользователя, а не группы.
- `message_thread_id` - ID темы, а не группы.

## Шаг 9. Получите ID канала

1. Убедитесь, что бот уже администратор канала.
2. Опубликуйте новый тестовый пост в канале:

```text
test channel
```

3. Снова откройте:

```text
https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/getUpdates
```

4. Найдите объект `channel_post`.
5. Скопируйте значение `channel_post.chat.id` целиком, включая минус.

Обезличенный пример:

```json
{
  "ok": true,
  "result": [
    {
      "update_id": 333333333,
      "channel_post": {
        "message_id": 7,
        "chat": {
          "id": -1009876543210,
          "title": "IncidentGPT Alerts",
          "type": "channel"
        },
        "text": "test channel"
      }
    }
  ]
}
```

Результат:

```bash
TELEGRAM_CHANNEL_ID="-1009876543210"
```

Что важно:

- `type: "channel"` подтверждает, что найден канал.
- `sender_chat.id` и `chat.id` обычно совпадают.
- Используйте именно `chat.id`.
- Знак минус необходимо сохранить.

## Что делать, если getUpdates возвращает result: []

Ответ может выглядеть так:

```json
{
  "ok": true,
  "result": []
}
```

Это не обязательно ошибка. Это означает, что у бота сейчас нет новых обновлений, которые можно показать.

Сделайте проверку по порядку:

1. Убедитесь, что бот добавлен в группу.
2. Отправьте новую команду после открытия `getUpdates`:

```text
/test@BOT_USERNAME
```

3. Обновите страницу `getUpdates`.
4. Для канала создайте новый пост после добавления бота администратором.
5. Снова обновите `getUpdates`.

Проверьте webhook:

```text
https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/getWebhookInfo
```

Если поле `url` непустое, значит бот настроен на webhook. Telegram не использует `getUpdates` и webhook одновременно.

Удалите webhook без очистки ожидающих обновлений:

```text
https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/deleteWebhook?drop_pending_updates=false
```

После удаления webhook:

1. Отправьте новое сообщение в группу или новый пост в канал.
2. Снова откройте `getUpdates`.

Другие причины пустого результата:

- команда отправлена до добавления бота;
- сообщение отправлено не в ту группу;
- username бота написан неправильно;
- бот удален из группы;
- бот не администратор канала;
- сообщение в канале было опубликовано до добавления бота;
- используется токен другого бота;
- обновления уже забрал запущенный экземпляр `ai-worker` или другой процесс;
- приложение использует webhook;
- обновления были очищены через `drop_pending_updates=true`.

> [!NOTE]
> Текущий `ai-worker` IncidentGPT не вызывает `getUpdates`. Если обновления исчезают, их мог забрать другой процесс или ручная проверка.

## Если токен случайно попал в Git или скриншот

1. Откройте `@BotFather`.
2. Отправьте или выберите `/mybots`.
3. Выберите нужного бота.
4. Откройте `API Token`.
5. Отзовите старый токен.
6. Создайте новый токен.
7. Обновите Kubernetes Secret или `values-secret.yaml`.
8. Перезапустите `ai-worker`.
9. Удалите токен из Git history, если он был закоммичен.

> [!IMPORTANT]
> Удалить строку из последнего коммита недостаточно. Старый токен остается в истории Git, пока история не очищена. Даже после очистки истории токен нужно считать скомпрометированным и заменить.

## Шаг 10. Заполните Telegram-конфигурацию IncidentGPT

В umbrella chart используется файл `deploy/incidentgpt/values.yaml`. Для секретов используйте отдельный локальный файл `values-secret.yaml`, который уже указан в `.gitignore`.

Не копируйте демонстрационные ID и токены в production.

Минимальный пример `values-secret.yaml`:

```yaml
ai-worker:
  secretValues:
    openrouterApiKey: "<OPENROUTER_API_KEY>"
    telegramBotToken: "<TOKEN_FROM_BOTFATHER>"
    sanitizerAuthSharedSecret: "<SAME_HMAC_SECRET_AS_SANITIZER>"

  env:
    TELEGRAM_CHANNEL_ID: "-1009876543210"
    TELEGRAM_THREAD_CHAT_ID: "-1001234567890"

incidentgpt-enricher:
  secretValues:
    sanitizerAuthSharedSecret: "<SAME_HMAC_SECRET_AS_SANITIZER>"

incidentgpt-sanitizer:
  secretValues:
    hashKey: "<LONG_RANDOM_HASH_KEY>"
    authSharedSecret: "<SAME_HMAC_SECRET_AS_SANITIZER>"
```

Если вы используете заранее созданный Kubernetes Secret, настройка может выглядеть так:

```yaml
ai-worker:
  secrets:
    existingSecret: "incidentgpt-ai-worker"
    openRouterApiKeyKey: "OPENROUTER_API_KEY"
    telegramBotTokenKey: "TELEGRAM_BOT_TOKEN"
    sanitizerAuthSharedSecretKey: "auth-shared-secret"

  env:
    TELEGRAM_CHANNEL_ID: "-1009876543210"
    TELEGRAM_THREAD_CHAT_ID: "-1001234567890"
```

Рекомендуемые строки в `.gitignore`:

```gitignore
values-secret.yaml
*.secret.yaml
.env
.env.local
```

В текущем репозитории `values-secret.yaml`, `.env` и `.env.*` уже игнорируются. Если вы используете имя `prod.secret.yaml`, добавьте правило `*.secret.yaml`.

## Шаг 11. Проверьте бота до запуска IncidentGPT

Задайте переменную в текущем shell. Не вставляйте токен в историю команд на общих машинах.

```bash
export TELEGRAM_BOT_TOKEN='<TOKEN_FROM_BOTFATHER>'
```

Проверка токена:

```bash
curl --request GET \
  "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/getMe"
```

Ожидаемый ответ:

```json
{
  "ok": true,
  "result": {
    "is_bot": true,
    "username": "orange_incident_bot"
  }
}
```

Проверка публикации в канал:

```bash
curl --request POST \
  "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/sendMessage" \
  --header "Content-Type: application/json" \
  --data '{
    "chat_id": "-1009876543210",
    "text": "IncidentGPT Telegram test"
  }'
```

Проверка сообщения в группу:

```bash
curl --request POST \
  "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/sendMessage" \
  --header "Content-Type: application/json" \
  --data '{
    "chat_id": "-1001234567890",
    "text": "IncidentGPT discussion test"
  }'
```

Ожидаемый результат для обеих проверок: JSON с `"ok": true`.

> [!NOTE]
> В текущей реализации IncidentGPT не использует `message_thread_id`, поэтому пример с `message_thread_id` для production-конфигурации не нужен.

## Частые ошибки

### `result: []`

Симптом: `getUpdates` возвращает пустой массив.

Причина: у бота нет новых обновлений, webhook забирает обновления, сообщение отправлено до добавления бота или обновления уже прочитал другой процесс.

Исправление: отправьте новую команду `/test@BOT_USERNAME`, обновите `getUpdates`, проверьте `getWebhookInfo`, при необходимости выполните `deleteWebhook?drop_pending_updates=false`.

### `Unauthorized`

Симптом: Telegram API отвечает `Unauthorized`.

Причина: неверный токен, лишний пробел, перенос строки или токен был отозван.

Исправление: скопируйте новый токен из BotFather, обновите Secret или `values-secret.yaml`, перезапустите `ai-worker`.

### `Bad Request: chat not found`

Симптом: `sendMessage` не находит чат.

Причина: бот не добавлен в канал или группу, ID скопирован неверно, удален знак минус, вместо ID указан invite link.

Исправление: добавьте бота, заново получите `chat.id`, сохраните ID строкой:

```yaml
TELEGRAM_CHANNEL_ID: "-1009876543210"
```

### `Forbidden: bot is not a member of the channel chat`

Симптом: бот не может отправить сообщение в канал.

Причина: бот не добавлен администратором канала.

Исправление: откройте канал, добавьте бота в администраторы, включите право публикации.

### `Forbidden: bot was kicked from the supergroup chat`

Симптом: бот не может отправить сообщение в группу.

Причина: бот был удален из группы или заблокирован.

Исправление: добавьте бота обратно и снова выдайте право отправки сообщений.

### `Not enough rights to send text messages to the chat`

Симптом: Telegram запрещает отправку текста.

Причина: у бота нет права отправлять сообщения в группе или публиковать в канале.

Исправление: проверьте права администратора в нужном чате.

### `Bad Request: message thread not found`

Симптом: Telegram сообщает, что тема не найдена.

Причина: где-то используется неверный `message_thread_id`.

Исправление: для текущего IncidentGPT не настраивайте `message_thread_id`; код его не отправляет. Если у вас форк с такой настройкой, получите ID темы из JSON Telegram API и не путайте его с `chat.id`.

### Бот пишет в группу, но не пишет в канал

Симптом: ручной `sendMessage` в группу работает, а в канал нет.

Причина: бот не администратор канала или нет права публикации.

Исправление: добавьте бота администратором канала и включите `Публиковать сообщения`.

### Бот пишет в канал, но сообщение не появляется в обсуждении

Симптом: пост есть в канале, но его нет в группе.

Причина: канал и группа не связаны через `Обсуждение`.

Исправление: откройте управление каналом, выберите `Обсуждение`, привяжите группу, затем опубликуйте новый тестовый пост.

### Перепутаны `TELEGRAM_CHANNEL_ID` и `TELEGRAM_THREAD_CHAT_ID`

Симптом: алерты уходят не туда или Telegram возвращает ошибку.

Причина: ID канала и группы вставлены наоборот.

Исправление: `type=channel` вставьте в `TELEGRAM_CHANNEL_ID`, `type=supergroup` вставьте в `TELEGRAM_THREAD_CHAT_ID`.

### У ID удален знак минус

Симптом: `chat not found` или сообщение уходит не туда.

Причина: скопировано `1009876543210` вместо `-1009876543210`.

Исправление: сохраните ID целиком, включая `-`.

### Вместо `chat.id` скопирован `update_id`

Симптом: Telegram не находит чат.

Причина: `update_id` - номер события, а не ID канала или группы.

Исправление: используйте только `message.chat.id` или `channel_post.chat.id`.

### Вместо `chat.id` скопирован `from.id`

Симптом: бот пишет пользователю или получает ошибку.

Причина: `from.id` - ID пользователя.

Исправление: скопируйте `chat.id`.

### Используется invite link вместо числового ID

Симптом: в values указан `https://t.me/...` или `t.me/+...`.

Причина: Telegram Bot API `sendMessage` ожидает `chat_id`, а не ссылку-приглашение.

Исправление: получите числовой `chat.id` через `getUpdates`.

### Токен содержит пробел или перенос строки

Симптом: `Unauthorized` или переменная выглядит настроенной, но Telegram не принимает запрос.

Причина: токен скопирован с лишним символом.

Исправление: вставьте токен заново без пробелов и переносов.

### В YAML сломаны отступы

Симптом: Helm не применяет значения или Pod стартует без переменных.

Причина: ключи `ai-worker`, `secretValues` и `env` находятся на неверном уровне.

Исправление: проверьте структуру:

```yaml
ai-worker:
  secretValues:
    telegramBotToken: "<TOKEN_FROM_BOTFATHER>"
  env:
    TELEGRAM_CHANNEL_ID: "-1009876543210"
```

### Числовой ID YAML интерпретирует неправильно

Симптом: значение выглядит как число, а не строка.

Причина: ID записан без кавычек.

Исправление: храните Telegram ID как строки:

```yaml
TELEGRAM_CHANNEL_ID: "-1009876543210"
```

а не:

```yaml
TELEGRAM_CHANNEL_ID: -1009876543210
```

### Бот получает обновления не через `getUpdates`, а через webhook

Симптом: `getUpdates` пустой, хотя сообщения отправлены.

Причина: у бота включен webhook.

Исправление: проверьте `getWebhookInfo` и удалите webhook через `deleteWebhook?drop_pending_updates=false`.

### Запущенный ai-worker забирает обновления раньше браузера

Симптом: обновления исчезают.

Причина: другой процесс вызывает `getUpdates`.

Исправление: остановите этот процесс на время получения ID. Текущий `ai-worker` IncidentGPT `getUpdates` не вызывает.

### Privacy Mode мешает читать обычные сообщения

Симптом: бот не видит обычный текст в группе.

Причина: Privacy Mode включен.

Исправление: для получения ID отправляйте команду `/test@BOT_USERNAME`. Для форка, который читает обычные сообщения, отключите Privacy Mode через `/setprivacy`.

### Канал и группа не связаны

Симптом: комментарии не появляются в группе.

Причина: в настройках канала не выбрана группа обсуждения.

Исправление: привяжите группу в разделе `Обсуждение`.

### Создана только группа, но отсутствует канал

Симптом: нет объекта `type=channel`.

Причина: создан чат для общения, но не канал для публикаций.

Исправление: создайте канал и получите его `chat.id`.

### Создан только канал, но отсутствует группа обсуждения

Симптом: алерты публикуются, но обсуждать их негде.

Причина: группа не создана или не привязана.

Исправление: создайте группу и привяжите ее к каналу.

### Пользователь создал две группы вместо канала и группы

Симптом: оба объекта в `getUpdates` имеют `type=supergroup`.

Причина: канал не был создан.

Исправление: создайте `New Channel`, а не еще одну группу.

### Пользователь создал тему форума и считает ее отдельным чатом

Симптом: вместо `chat.id` используется `message_thread_id`.

Причина: тема форума находится внутри группы и не является отдельным чатом.

Исправление: используйте `chat.id` группы для `TELEGRAM_THREAD_CHAT_ID`. В текущем коде отдельный `message_thread_id` не настраивается.

## Что именно куда вставлять

| Что получили | Куда вставить |
|--------------|---------------|
| Токен от BotFather | `TELEGRAM_BOT_TOKEN` или `ai-worker.secretValues.telegramBotToken` |
| `chat.id` объекта `type=channel` | `TELEGRAM_CHANNEL_ID` |
| `chat.id` объекта `type=supergroup` | `TELEGRAM_THREAD_CHAT_ID` |
| ID темы форума | Только в настройку `message_thread_id`, если такая настройка есть в вашем форке |


Telegram вернул:

```json
{

  "id": -1001234567890
}
```

Значит:

```bash
TELEGRAM_THREAD_CHAT_ID="-1001234567890"
```
